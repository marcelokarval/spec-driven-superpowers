## ADDED Requirements

### Requirement: Partial readiness
The toolkit SHALL support partial readiness with explicit evidence boundaries.

#### Scenario: Partial readiness
- **WHEN** the corresponding workflow is evaluated
- **THEN** A valid graph retains incomplete future contracts, while ready independent tasks remain eligible. Invalid graphs and strict v1 calls still fail.

### Requirement: Continuity
The toolkit SHALL support continuity with explicit evidence boundaries.

#### Scenario: Continuity
- **WHEN** the corresponding workflow is evaluated
- **THEN** After accepting A, the next decision selects authorized eligible B; status preserves state, explicit pause blocks dispatch, and a validation blocker remains scoped. All tasks accepted requests objective verification.

### Requirement: Discovery
The toolkit SHALL support discovery with explicit evidence boundaries.

#### Scenario: Discovery
- **WHEN** the corresponding workflow is evaluated
- **THEN** Known compatible CLI outside PATH is reusable. Versions, inaccessible programs, project configuration and capability uncertainty are distinct; diagnosis installs nothing and preserves refusal.

### Requirement: Source fidelity
The toolkit SHALL support source fidelity with explicit evidence boundaries.

#### Scenario: Source fidelity
- **WHEN** the corresponding workflow is evaluated
- **THEN** An existing plan projection remains bound to original source hashes and unique anchors; changed sources refuse admission. Declared approval criteria require fresh integrated evidence.

### Requirement: Host boundary
The toolkit SHALL support host boundary with explicit evidence boundaries.

#### Scenario: Host boundary
- **WHEN** the corresponding workflow is evaluated
- **THEN** Host invocation checks authorization and current sources, reserves before project work and retains reservations on uncertain start. Natural-entry harness qualification is recorded separately.
