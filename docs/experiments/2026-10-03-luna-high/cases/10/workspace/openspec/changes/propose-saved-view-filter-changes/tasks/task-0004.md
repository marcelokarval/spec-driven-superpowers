# Task 0004: Recover through compensation

## Outcome

Allow an operator to restore a retained prior filter snapshot through a new proposal and explicitly authorized operation.

## Inputs

Read project rules and the proposal, design, capability spec, and integrated contracts from Tasks 0001–0003.

## Acceptance

- Recovery selects an existing prior snapshot and presents a preview against the current view/version.
- Recovery uses a new operation ID bound to its canonical content, requires separate current permission and expected-version match, and is safe to retry.
- Successful recovery restores prior filters, increments the current version once and appends a compensating result without changing prior records.
- Invalid permission, stale version, ID conflict or failed transaction leaves current state and operation history unchanged.

## Verification

Use TDD and run `node --test tests/app.test.mjs`. Cover preview, successful compensation, exact retry, identifier conflict, stale version, invalid permission and transaction failure.

## Definition of done

Return scoped code and test evidence bound to one revision. Coordinator verifies that recovery composes with normal proposal/apply behavior and preserves the full prior history.

## TDD

RED: add recovery tests for success and rejection paths. GREEN: route recovery through the shared proposal, permission and transaction contract. REFACTOR: avoid a second authorization or idempotency implementation.

## Boundaries and delivery

Write only `src/app.js`, `index.html`, `src/styles.css` and `tests/app.test.mjs`. Do not include sharing, remote recovery or deletion of historical records.
