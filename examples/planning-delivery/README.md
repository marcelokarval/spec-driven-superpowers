# Modelos de entrega de planejamento

Todos os dados destes modelos são **sintéticos**: intenção, autorização, revisão,
readback e caminhos de projeto ilustrativos. Não houve execução do catálogo,
revisão independente viva nem publicação. Hashes são reais dos arquivos-fixture,
não prova de entrega real. Os testes conferem integridade e compatibilidade, não
qualidade semântica ou o comportamento de um agente em sessão nova.

- [Completo](complete/tasks.md): planejamento delivered, pedido original de software ainda não cumprido.
- [Parcial](partial/tasks.md): listagem utilizável; exportação e guia afetados por formato não decidido.
- [Bloqueado](blocked/tasks.md): gate global de revisão independente exigida, indisponível; não entregar ready.

Cada pasta é um pacote-modelo autônomo, não cópia de instalação/staging nem
estratégia de persistência. Comece por brief.md, leia índice/contratos, reviews.md
e planning-manifest.json. Índices e checkboxes são trabalho futuro aberto.
Ver [contrato normativo](../../docs/architecture/planning-delivery-contract.md).
